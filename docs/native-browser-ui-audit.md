# Native browser UI audit

This inventory covers browser-native controls and prompts rendered or invoked by `apps/web/src`. It also notes the end-to-end tests that depend on them. The app uses several Vue popovers, menus, and ARIA dialogs that provide patterns for in-app replacements.

## Existing in-app patterns

- [`ContextMenu.vue`](../apps/web/src/components/ContextMenu.vue) renders a positioned `role="menu"` with button menu items, keyboard navigation, focus handling, and screen-edge positioning. [`menu.ts`](../apps/web/src/components/menu.ts) describes its items.
- [`FormulaAssist.vue`](../apps/web/src/components/FormulaAssist.vue) renders an anchored `role="listbox"` for formula suggestions.
- [`CellError.vue`](../apps/web/src/components/CellError.vue) renders an anchored, teleported tooltip or dialog with error details.
- [`FormulaSessionHost.vue`](../apps/web/src/components/FormulaSessionHost.vue) renders a teleported modal backdrop and a `role="dialog"` with `aria-modal`, a focus trap, and Escape handling.
- [`DialogHost.vue`](../apps/web/src/components/DialogHost.vue) renders the shared promise-based confirmation, prompt, and alert dialogs used across the app.
- [`ResizeTable.vue`](../apps/web/src/components/ResizeTable.vue), [`SharePanel.vue`](../apps/web/src/components/SharePanel.vue), [`HistoryPanel.vue`](../apps/web/src/components/HistoryPanel.vue), [`ErrorsPanel.vue`](../apps/web/src/components/ErrorsPanel.vue), and [`AssertionsPanel.vue`](../apps/web/src/components/AssertionsPanel.vue) use ordinary Vue elements with dialog semantics. They are not native `<dialog>` elements.
- [`ColumnFormulaPopover.vue`](../apps/web/src/components/ColumnFormulaPopover.vue) is an in-flow editor popover.

## Browser prompts and confirmations

`apps/web/src` has no `window.prompt`, `window.confirm`, or `window.alert` calls. `useDialog()` in [`useDialog.ts`](../apps/web/src/useDialog.ts) provides promise-based `confirm`, `prompt`, and `alert` methods; [`App.vue`](../apps/web/src/App.vue) mounts one `DialogHost` for the app. The host uses accessible dialog roles, labels, focus trapping and restoration, safe initial focus, Escape cancellation, and a phone-width layout. Prompt inputs receive focus and accept Enter.

## Other requested browser UI

- No `<datalist>` or native `<dialog>` element appears in `apps/web/src`.
- `role="dialog"` elements and overlays listed above are in-app Vue UI, not native dialog elements.
- The formula and view-source editor uses CodeMirror's contenteditable editor. [`FormulaEditor.vue:121`](../apps/web/src/components/FormulaEditor.vue#L121) sets whether it is editable; the generated `.cm-content` element is `contenteditable="false"` in read-only mode, as checked in [`FormulaEditor.test.ts:144`](../apps/web/src/components/FormulaEditor.test.ts#L144) and [`ChartCard.test.ts:241`](../apps/web/src/components/ChartCard.test.ts#L241). There is no app-authored `contenteditable` attribute.
- The word `alert` also appears in ARIA `role="alert"` status messages and security test strings. Those are not `window.alert` calls.

## End-to-end dependencies

The end-to-end tests for version restore, chart deletion, stopping a share, and table resize now locate the in-app dialog and click its action button. The screenshot flow enters a formula in the column editor. No Playwright test needs a `page.on("dialog")` handler.

## Replacement priorities

Effort estimates compare shared in-app components with replacing each use independently.

| Priority | Current UI                                                         | User-visible annoyance                                                                                                  | Effort         | Replacement                                                                                                                                                                                                                                                                                            |
| -------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1        | `window.confirm` calls                                             | High: browser-owned prompts interrupt the task and vary by browser.                                                     | Complete       | One promise-based `useDialog()` service and `DialogHost.vue` handle all 13 confirmations with clear action text and destructive styling. The router guard awaits the answer. Keep `beforeunload` for pending saves because browsers control that prompt.                                               |
| 2        | Native `<select>` elements                                         | High: menus use browser- and platform-specific popup behavior throughout the editor.                                    | High           | Build a reusable trigger-and-popover choice control. Use an accessible listbox with selected state for values, and `ContextMenu` for command-like choices. Use a swatch grid inside the popover for colors. Preserve keyboard selection, Escape, focus return, scrolling, and type-ahead where useful. |
| 3        | Native `title` tooltips                                            | Medium: they appear after browser-controlled delays and placement and can duplicate visible labels.                     | Medium         | Replace informative titles with a small app tooltip based on the positioning and accessibility patterns in `CellError.vue`. Keep `aria-label` and visible text as the accessible name; omit redundant tooltips when the control already says what it does.                                             |
| 4        | Ordinary text, email, password, number, radio, and checkbox inputs | Low: these are familiar data-entry controls, though browser validation bubbles and number spinners can be inconsistent. | Low to medium  | Keep native input semantics and style them with the existing field classes. For fields that need explanatory validation, show the existing inline `notice` pattern instead of relying on browser validation bubbles.                                                                                   |
| 5        | File inputs                                                        | Low to medium: the file chooser is browser or operating-system UI, but users expect it for choosing a local file.       | Low            | Keep the native file chooser for document import and the table menu's `Import CSV` and `Append CSV rows` actions. Use the shared confirmation modal for overwriting data.                                                                                                                              |
| 6        | CodeMirror contenteditable editor                                  | Low: it is an intentional editor built around syntax highlighting, formula completion, and keyboard behavior.           | Not applicable | Keep CodeMirror. It is already app-managed and supplies editing behavior a plain contenteditable region does not.                                                                                                                                                                                      |
